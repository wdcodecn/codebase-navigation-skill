# Codebase Navigation 技能

让 AI 更快找到正确仓库、入口和实现 owner，并在后续会话中复用有效上下文。
适用于单仓、monorepo 和多仓工作区。

[English](README.md) · [技能正文](skills/codebase-navigation/SKILL.md)

## 能做什么

- 把业务说法、报错、URL 对应到实际代码入口。
- 连接调用方、状态 owner、跨组件接口和必要约束，减少重复研究逻辑。
- 按问题选择精确搜索、结构图、语言服务、历史或运行证据。
- 让新会话按需读取已有导航，避免默认加载整套项目说明。
- 在需要时设计随任务触发、增量执行、完成后退出的索引维护。

CodeGraph、LSP 等都是可选手段。技能会先看项目已有能力和真实缺口，
不会要求安装一整套工具，也不会把某个工具作为所有任务的必经入口。

**本仓库提供技能、参考说明和地图模板，不包含一键安装器、常驻服务或
预配置的自动更新程序。** 需要自动维护时，由 AI 依据实际工具和宿主能力
生成适合当前环境的实现，并核验是否真的生效。

## 安装

把 `skills/codebase-navigation/` 复制到所用 AI 工具支持的技能目录。
以 Codex 为例：

```sh
git clone https://github.com/wdcodecn/codebase-navigation-skill.git
mkdir -p ~/.codex/skills
cp -R codebase-navigation-skill/skills/codebase-navigation ~/.codex/skills/
```

如果目标已存在，先比较版本，保留自己的适配，不直接覆盖。
未自动发现时启动新会话。其他 AI 工具请使用其支持的技能目录和安装方式；
没有技能发现机制的工具，也可以直接读取本仓库的 `SKILL.md`。

## 用法示例

> 使用 $codebase-navigation 优化当前工作区。AI 总在重复找代码、研究同一段
> 逻辑。先找真实的导航缺口，复用现有文档，让新会话能快速定位。如果索引需要
> 自动维护，就按宿主支持的事件增量更新，执行完退出，不增加后台常驻服务。

也可以限定范围：

> 只整理跨仓代码导航，补上入口、职责、状态 owner 和接口边界，不改业务、CI。

> 检查索引为何在新增功能后过期，配置低开销的按需刷新，不影响其他项目。

具体任务约束优先。调用技能本身不授权发布、访问生产、上传私有源码、
安装外部服务或修改 CI。

## 验证与边界

用少量真实问题核对能否找到正确 checkout、owner 和上下游；改了维护脚本，
再检查无变化退出、重复修改、并发、失败和资源占用。这里不要求新建产品测试
体系或 CI。

代码索引能确定性更新，业务语义仍由修改相关入口或规则的 AI 维护。
不能把“写了一句记得更新”当作自动化，也不能把 hook 文件存在当作已经启用。
某些宿主要求首次信任 hook，必须走其支持的机制。

资料来自公开实践，包含 2026 年 Stripe、Uber 与相关研究；链接见
[来源说明](skills/codebase-navigation/references/sources.md)。没有附带任何私有
项目源码、索引、会话日志、本机配置或个人绝对路径，也不承诺未经实测的提速比例。
